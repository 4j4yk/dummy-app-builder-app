Integration POC

Commerce → Node.js → Target

Minimal, working proof that order data can flow from a commerce (Magento-compatible) source through a Node.js “App Builder-like” action and into a target endpoint.

View on GitHub Run Locally API

GitHub Pages hosts this documentation only. The Node service runs locally (or on a host such as Render/Fly/EC2 later).

What this proves

  • Fetch recent orders from Mage-OS REST API
  • Invoke an action with an App Builder-like signature (main(params))
  • Enrich and send a slimmed payload to a warehouse-like endpoint
  • Persist forwarded IDs locally (data/sent.json) to avoid resending after restart

Architecture

Commerce (REST: /V1/orders)
    ↓
Node runner (poll or manual trigger)
    ↓
Action: actions/pipeline-order.js
    ↓
Warehouse ingest (local JSONL)

Run locally (macOS)

  1. Install Node.js 20+ (Homebrew): brew install node
  2. Install deps: npm install
  3. Create env: cp .env.example .env
  4. Set COMMERCE_BASE_URL (e.g. https://<domain>/rest/all/V1)
  5. Set COMMERCE_ACCESS_TOKEN (integration token preferred)
  6. Ensure PIPELINE_MODE=true (default)
  7. Start: npm start
  8. Trigger one cycle: curl -X POST http://localhost:3000/run/poll-once
  9. Demo order (no Commerce order needed): curl -X POST http://localhost:3000/run/demo-order
Tip: If you see “Cannot GET /target/orders”, that’s expected. The dummy target is a POST endpoint. For the pipeline, the warehouse endpoint is POST /warehouse/ingest.
